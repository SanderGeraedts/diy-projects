# Context

By v1, 16 of 26 tasks still said *Doing* although their code had been reviewed, merged and
was running in production. Stacked branches and one integration PR (#37) carried many
tasks at once, and nobody went back to the task files. The index was edited by hand and
drifted from the files. Sander wants the task list to show reality at all times, so he
doesn't have to reconstruct it from PRs and chat.

# Decision

- **Same PR:** the PR that starts work on a task sets it to *Doing*; the PR that delivers
  it adds itself to `result` and a *Log* line with the check's actual output. A PR that
  carries several tasks (stacked or integration) updates every one of them.
- **Done or Remaining:** when every *Done when* item is met, the task is *Done* with
  `done_on`. When an item needs Sander after the merge (a check on his phone, a review), the
  task stays *Doing* and its last *Log* line starts the open items with `Remaining:`.
- **Record confirmations right away:** when Sander confirms a remaining item in chat, the
  agent records it in the task file in that session, in a PR that touches only
  `docs/tasks/` (unguarded, so it merges itself).
- **Generated index:** `docs/tasks/index.md` is generated by `pnpm run tasks:index` from
  the task files' front matter and never edited by hand. `pnpm test` runs the same script
  with `--check` and fails when the index is out of step, a *Done* task has no `done_on`, a
  task that isn't *Done* has one, or a *Doing*/*Done* task has an empty *Log*.

# Rationale

Updating the task in the PR that does the work costs one line and keeps the record next to
the code that proves it. A generated, checked index can't drift. Keeping post-merge checks
as `Remaining:` makes the *Doing* list the one place where Sander sees what still waits on
him, instead of a list of PRs.

# Consequences

- A PR that changes a task's status without regenerating the index fails CI.
- The check can't know whether work was merged; an agent starting a session still looks at
  *Doing* tasks whose PRs are merged and asks Sander about their `Remaining:` items.

# Guidance for agents

- Change a task's front matter and *Log* in the same PR as the work; then run
  `pnpm run tasks:index` and commit the index.
- Never hand-edit `docs/tasks/index.md`.
- At the start of a session, read the *Doing* list; for each task whose PR is merged and
  whose `Remaining:` items Sander has confirmed, set it to *Done* in its own docs-only PR.
- D-0008 still applies: *Done* only after its check ran, with the actual output in the Log.
